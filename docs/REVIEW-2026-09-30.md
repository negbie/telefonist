# Telefonist review — 2026-09-30

Historical review of the pre-change code. See [0.9 implementation and upgrade notes](UPGRADE-0.9.md) for the fixes, changed defaults, verification results, and remaining limitations.

This review covers the Go orchestrator, agent transport, storage and HTTP routes, frontend modules, custom audio/presence/codec code, build machinery, existing tests, and the two supplied screenshots. Findings below are source-derived unless explicitly described as tested. The Linux application and native modules were not compiled or exercised here. No production behavior was changed.

The central recommendation: make a run a durable, isolated object with trustworthy evidence. Then organize the UI around that run. A faster log viewer cannot compensate for missing evidence or ambiguous PASS results.

## Fix first: correctness and evidence

### 1. Dropped telemetry can invalidate results without invalidating the run

Locations: `pkg/gobaresip/gobaresip.go:340,398`; `pkg/telefonist/ws_hub.go:187`; `pkg/telefonist/ws_broadcast.go:5`.

There are multiple nonblocking sends that drop events/responses when queues fill. The C callback path silently drops; the master logs drops but leaves the verdict machinery unaware. Losing a REGISTER_FAIL or events used by an assertion can alter the result. Increasing queue capacities only postpones this.

Separate authoritative recording from best-effort UI delivery. Count loss at each boundary and mark an affected run ERROR/incomplete. Avoid blocking a real-time audio callback on browser or disk work: use a bounded capture queue with explicit overflow reporting. Bound by bytes as well as message count. Run lifecycle messages need reliable delivery and a recoverable status endpoint.

Regression: deliberately saturate capture with a known sequence; the run must either contain every event or finish ERROR, never silently PASS.

### 2. The hub performs blocking orchestration inside its event loop

Locations: `ws_hub.go:240,400`; `manager.go:128,383`.

An unchained command runs synchronously in `WsHub.Run`. `uanew` waits for connection/registration, `uadelall` waits for process shutdown, and command writes can block. Meanwhile the hub cannot consume telemetry, registration requests, or stop commands. Manual commands also bypass `chainMu` and can interfere with a test or another command chain. A mutex protecting a pointer does not provide run isolation.

Introduce one bounded command executor and explicit run ownership. The hub should only route messages and update state. Reject or explicitly queue manual mutations during a test. Never create an unbounded goroutine per submitted chain.

Regression: inject a slow agent startup and verify the hub still records telemetry and accepts Stop; attempt a manual command during a run and verify an explicit refusal or queue policy.

### 3. Stop/shutdown has indefinite waits and incomplete context propagation

Locations: `ws_hub.go:201`; `ws_testfile_inline.go:62,137,336`; `websocket.go:41,184`; `run.go:100`.

`Drain` times out while enqueueing its sentinel, but the subsequent `<-done` has no timeout. `checkTestFailure` also waits unconditionally for an actor callback. When the hub has exited, accepted callbacks are never executed. Several internal/broadcast/register/unregister sends have no cancellation case. Each WebSocket read pump creates a goroutine that survives disconnect until hub shutdown. Agent startup receives `h.ctx`, not the current test context, so cancelling a test does not immediately cancel registration.

Use context-aware actor requests with acknowledgements, a hub completion channel, and a joined shutdown sequence: stop admission/scheduler, cancel execution, terminate agents, finalize evidence, close clients, stop hub, close storage. Tie each connection watcher to connection lifetime. Pass the execution context through all command operations.

Regression: cancel during startup, a delay, JS evaluation, finalization, and an already-enqueued drain; all workers must exit within a deadline.

### 4. Commands can fail without failing the test

Locations: `ws_hub.go:400`; `manager.go:448`; `gobaresip/commands.go:90`; `ws_testfile_inline.go:230`.

Missing agents and command transport errors only log. Negative baresip responses are displayed without checking `Ok` or linking them to a pending step. A mistyped explicit target falls through target resolution. With no hash or assertion script, such a test can reach PASS.

Return structured errors from command execution and correlate acknowledgements using opaque request IDs. Fail on missing targets, negative responses, disconnects, and acknowledgement timeouts unless the step explicitly expects that error. Expose the failing line, command, agent, and reason.

Regression: unknown agent, closed transport, negative command response, and missing acknowledgement must each produce a persisted failure.

### 5. Evaluation does not receive the same evidence as the UI

Locations: `ws_hub.go:300`; `training.go:82`; `evaluator.go:27`; README advanced validation example.

The hub discards CALL_RTCP before recording, even though the documented validator uses it. Events are recorded from `RawJSON` before `EnrichMessage` adds time. Thus normal saved agent events lack the live UI timestamp. SIP trace direction/method are embedded in `param`, not the structured `direction`/`method` fields used by the README example. `stats` is always empty. The evaluator does no normalization to repair this contract.

Create one versioned event envelope at ingestion: run ID, sequence, agent ID, capture timestamp, monotonic elapsed time, event kind, call ID, and typed payload. Store and evaluate that same envelope; keep raw SIP bytes separately. Presentation filters must not remove evidence needed by assertions. Parse SIP with a defined contract and document time units.

Regression: send RTCP and a call lifecycle through the actual hub, persist and reload the run, then execute the shipped example validators. Testing `TrainSession.recordEvent` alone cannot catch the hub dropping RTCP.

### 6. Aborted and some infrastructure-failed runs disappear from history

Locations: `ws_testfile_inline.go:253`; `teststore.go:1042`; `run.go:123`.

The cancelled path broadcasts a result and returns before `SaveRun` and recording collection. Registration failure cancels the test and follows this path. Parse failures also only broadcast. Store initialization failure allows the application to continue with persistence disabled. Runs have no stored failure reason, executed source snapshot, start/end times, or explicit aborted/error status.

Create the run record before execution, finalize it on every exit path, and preserve partial evidence. Store the exact executed test content and validator revision, with account aliases/configuration references but no credential values. Use PASS, FAIL, ERROR, ABORTED, SKIPPED, and UNVERIFIED. Report persistence failure to the UI instead of implying that a successful run was saved.

Regression: registration failure, user stop, invalid script, and storage error all leave an inspectable run with the right reason.

### 7. Recording finalization can destroy evidence

Locations: `ws_testfile_inline.go:463`; `teststore.go:1088,1161`.

`processRecordings` deletes the source after storage/location errors and ultimately removes the entire agent directory. It runs before the batch's final `CloseAll`; a script that omits `uadelall` can still have live writers. On Linux, moving an open file can allow continued writes, but this does not establish that the WAV header is finalized or the artifact complete. A failed `SaveRun` leaves runID zero and feeds this destructive path. Repeated runs are not guaranteed clean agent state unless scripts arrange it.

Make cleanup unconditional orchestration, not script etiquette: stop/join agents and telemetry forwarding, finalize the recording, then commit artifact metadata. Keep failed transfers in a quarantine/spool directory for retry. Use run/agent/call IDs in paths, and never delete the only copy on persistence failure.

Regression: omit cleanup in the script; simulate an unwritable destination or metadata failure; verify source evidence survives and artifacts are not attributed to a later repetition.

### 8. Retention prunes metadata but leaks WAVs

Locations: `teststore.go:1042,1752`.

Every save keeps only the latest 100 runs globally. SQL cascading removes WAV rows but not the actual files. This can erase one project's history because another is busy while steadily consuming disk with unreachable recordings.

Use configurable retention per project/test plus age/byte budgets and pinned baselines. Delete artifacts through a recoverable deletion job, and reconcile orphan files. Stable run-ID paths greatly simplify this. Do not VACUUM after routine individual deletions: it blocks the single database connection and does not fix orphan files.

Regression: prune runs containing WAVs; retained artifacts remain readable, pruned artifacts disappear, and another project's retention policy is unaffected.

### 9. Filesystem deletion accepts unsafe identity components

Locations: `teststore.go:316,488`; `api_handlers.go:241`.

`Delete` validates the testfile name but not the project before calling `RemoveAll`. DELETE HTTP query parameters reach this method unchanged. A project containing parent components can escape the recording root, and deletion happens before confirming a matching database row. Even shared validators accept `.` and `..` as complete names. This is a destructive authenticated endpoint, not merely a cosmetic input problem.

Validate every path component, reject dot components, prove containment, and look up the stored object before deletion. Prefer stable artifact IDs instead of user-visible names in paths. Handle symlinks deliberately. Add negative tests confined to a temporary sandbox, with an external sentinel file that must survive.

### 10. Rename and project deletion can desynchronize storage

Locations: `teststore.go:517,1465,1495`.

Rename moves directories before SQL success, logs filesystem failures but continues, and updates paths separately. SQL rollback cannot roll back filesystem changes. `DeleteProject` moves testfiles to the unnamed project but leaves recording locations in the old project directory; subsequent deletion derives a different path. The unnamed project and the literal project `default` share a path namespace. Prefix-wide SQL LIKE updates also treat `_` in project names as a wildcard.

Store artifacts under immutable run IDs and make names metadata only. Until then, reject conflicting renames and implement a recoverable journal for file moves, with exact path matching. Test collisions and partial failures, not only successful rename cycles.

### 11. Text substitution can corrupt account references

Locations: `ws_testfile_inline.go:355,547`; `cmdchain.go:74`.

The supposed whole-word account substitution is `ReplaceAll(sequence, " "+name, ...)`. With accounts `test1` and `test10`, resolving `dial test10` can substitute the `test1` prefix. It can also alter ordinary message text. Prefix expansion handles only selected whitespace patterns. `_define` performs unrestricted cascading replacements, with no tie-breaker for equal-length keys. `splitByPipe` compares a ten-byte slice with the nine-character string `auth_pass=`, so its secret mode never starts.

Parse once into steps and arguments; resolve only explicit account references, with defined quoting/escaping. Separate display alias, SIP AOR, and filesystem identity. Validate directives before starting agents and show line/column errors. Preserve the simple text DSL, but give it a real grammar.

Regression: `test1`/`test10`, tabs/multiple spaces, quoted message text, pipe-containing passwords, malformed `_run`, and unknown directives.

### 12. PASS currently conflates execution, baseline capture, and validation

Locations: `ws_testfile_inline.go:156,230`; `training.go:23,170`.

An empty or `_run 0` test reports PASS. No hash and no script also reports PASS. If both hash and script are supplied, the script branch bypasses the hash comparison. The hash intentionally ignores event order and most `param` values; its field removal is byte-pattern based and does not handle escaped JSON strings correctly. A hash match is useful as a regression signal, but it cannot establish call order, timing, or media quality.

Make baseline capture explicit and unverified runs visibly UNVERIFIED. Keep hashes as an optional versioned comparison mode; introduce semantic assertions with expected counts, forbidden events, ordering, and timing tolerances. If both checks are requested, execute both or reject the combination explicitly. Normalize parsed fields rather than editing JSON bytes.

### 13. Evaluator cancellation works, but there is no default timeout

Location: `evaluator.go:27`.

The evaluator interrupts when its context is cancelled; the new portable test verifies this. The normal caller only creates cancellation contexts, so an infinite script can block the single execution slot indefinitely until someone presses Stop. Malformed log entries are silently discarded as well.

Set a configurable evaluation deadline and a run wall-clock deadline. Bound event input, reject corrupt evidence, and expose script filename/line diagnostics. Do not advertise an execution timeout until one is actually supplied.

## Native and transport issues

### 14. G.722 output capacity checks occur too late or not at all

Location: `pkg/gobaresip/g722/g722.c:149`.

`g722_encode` writes to the caller's buffer before comparing returned length against capacity. `g722_decode` is called without first comparing required samples against incoming `*sampc`. The bundled library headers show neither function accepts a capacity argument. This is a source-level buffer-safety defect; exploitability and actual caller buffer sizes need Linux/native verification.

Validate lengths and integer conversions before invoking the codec. Add an ASan/UBSan harness for undersized output buffers, odd samples, empty packets, and oversized input. Consider removing this custom module if its required behavior can be supplied by the upstream codec; verify compatibility before doing so.

### 15. Audio modules need bounded I/O and more useful metrics

Locations: `aufile/aufile_src.c:75,156`; `aufile/aufile_play.c:112`; `audioreport/audioreport.c:8` under `pkg/gobaresip`.

The source loads the entire audio file and rereads it at loop boundaries on the pacing thread, introducing memory growth and I/O stalls. Player allocation errors after `mem_zalloc` return without releasing state; second-resolution output names can collide. The report reduces packet counts to `>10` booleans, which says little about quality or one-way audio over a long call.

Use a bounded producer buffer or an immutable cached loop sample, unique call/stream filenames, one cleanup path for allocation failures, and Linux native leak tests. Preserve packet/loss/jitter/duration/codec metrics and use known-tone or signal checks where they answer a real test question. Avoid claiming MOS from packet counts alone.

Presence currently emits only the first matching dialog state per subscription and regex-matches one XML state (`presence/subscriber.c`). Document this limitation or model dialog IDs, version, full/partial notifications, and state transitions; test actual NOTIFY fixtures with multiple dialogs and namespaces.

`patches.txt` also changes an audio-player startup error into a successful return and disables transfer capability/hold checks. Those may be intentional test behaviors, but silent global patches hide failures and change what the client is testing. Make them explicit, named test options, and persist the chosen options with each run. Player startup failure should remain visible as an infrastructure error unless the scenario deliberately tolerates it.

### 16. Agent lifecycle and port allocation are fragile

Locations: `manager.go:54,96,128,282,383`.

The RTP upper limit is ignored, ranges grow without a 65535 check, SIP addresses use string formatting instead of IPv6-safe joining, and a temporary TCP listener is closed before the child binds its port. Startup holds the manager lock through retries. Failed startup kills without `Wait`, risking unreaped children. Exit cleanup is keyed by alias rather than checking agent identity, so late cleanup can target a replacement using the same alias. The directory name is a raw AOR and can exceed Unix socket path limits.

Use stable short agent IDs, explicit lifecycle states, identity-checked cleanup, and guaranteed process reaping. Validate ranges and capacity. Prefer an agent readiness handshake with its actual bound control endpoint. Treat unexpected agent exit as a run error and retain startup logs.

### 17. Proxy lifetime and netstring parsing need hard limits

Locations: `gobaresip.go:695`; `netstring.go:24` under `pkg/gobaresip`.

The proxy waits only for `closeCh` when a forwarding goroutine exits; a disconnected master does not cancel the connection group. Old message consumers may survive while another connection starts. Proxy writes have no deadlines. Netstring length prefixes and payloads are unbounded, and a missing/incorrect comma is accepted rather than rejected.

Cancel and join all three forwarding directions on the first terminal error. Enforce deadlines, a maximum header/payload size, and strict framing. Keep C callbacks off blocking network paths. Add split-read, concatenated-frame, truncated-frame, invalid-delimiter, oversized-length, disconnect, and reconnect tests using pipes or local sockets.

### 18. PCAP export is synthetic and IPv6 can panic

Location: `pkg/telefonist/export.go:138`.

Export always creates IPv4/UDP headers, including for SIP originally sent over TCP/TLS. An IPv6 address passes `net.ParseIP` but `To4()` returns nil and is indexed. Payload normalization changes original bytes, and fallback addresses/timestamps invent missing data.

Label this clearly as a reconstructed SIP capture; preserve raw payload and capture timestamps. Either support IPv6 explicitly or return a clear unsupported error. Prefer real packet capture when transport-level analysis is required. Test IPv4/IPv6, SDP body lengths, malformed traces, and packet timestamps.

## Frontend and UX

### 19. Fix editor integrity before redesigning it

Locations: `assets/web/testfile_manager.js:121,175,200,306`; `assets/web/api.js:23`.

- Save captures the entry/content but updates `activeKey` when the request completes. Save A, switch to B, and A's content becomes B's saved baseline. Capture the key and request revision before starting the request.
- Project actions pass `{ project: name }` outside the callback that binds `name`. In a browser this can resolve to legacy `window.name`, not the prompted project. Pass the returned/canonical project identity through the action result.
- Each individual finished/error message flips the global running boolean, including busy rejections and gaps between batch files. The UI can enable Run and disable Stop while a batch is active. Use server batch/run state, not inferred log state.
- Single-file Run uses editor content; multiselect Run uses saved content. Make this distinction explicit and preserve exact source in run history.
- The API helper calls `response.json()` on plain-text HTTP errors. Handle non-2xx responses consistently and show actionable errors instead of unhandled promise rejections.
- Drafts are memory-only and there is no unload protection. Provide recovery for unsaved edits and optimistic concurrency on saves from multiple tabs.

Regression tests should use delayed fetch promises and simulated user actions; checking only the state-manager helper will miss the save race.

### 20. Reconnect and bounded rendering matter more than micro-optimizations

Locations: `socket_handler.js`; `dom.js`; `diff.js`; `compare_window.js:149`; `websocket.go:19`.

There is no reconnect or authoritative state resynchronization. `payloadQueue` is unbounded and depends on animation frames, which can be throttled when hidden. DOM batching is already a useful optimization, but three views can retain thousands of rich nodes each. LCS comparison allocates `(m+1)*(n+1)` uint32 cells on the main thread: two 10,000-item inputs require roughly 400 MB for that matrix alone. `unshift` adds further work. SIP comparison includes sequence number in its key, so an inserted packet shifts later matches.

Reconnect with backoff and sequence cursors; obtain a status snapshot before enabling commands. Bound queued bytes and display a gap/resync indicator. Virtualize visible rows, batch by time budget, cancel stale comparison/fetch work, and move substantial diffs into a worker with size limits. Remove absolute sequence numbers from alignment keys. Reduce 4 MiB per-direction WebSocket buffers independently of the permitted message size and benchmark real captures before tuning further.

Measure: heap after a long run, background-tab backlog, reconnect recovery, time to first useful run detail, search latency, diff latency, and disk bytes per run. No throughput benchmark was run in this review.

### 21. Organize the screenshots around a selected run

The screenshots show strong raw inspection capabilities but little hierarchy: three always-visible telemetry panes dominate the top, settings share space with unrelated old logs, names are truncated, and important results are tiny separators. The image was resized, so font conclusions also rely on CSS: several content/control sizes are 10.5–12px.

Recommended layout:

1. Persistent project/test navigation with full names, search, latest outcome, and an unsaved badge.
2. A prominent execution bar: selected environment, Run, Stop, connection state, current step, elapsed time, and queue length.
3. Main modes: Tests, Runs, Schedules, Settings. Settings gets the full workspace.
4. A run detail view opens with outcome and the precise failing assertion/step, then tabs for Timeline, SIP, Logs, Audio, and Assertions. Keep the current three-pane layout as an optional expert workspace.
5. Synchronize selections across views by event/call/agent ID. Clicking a failed step takes you to the corresponding SIP exchange and log interval.
6. A true participant-lane SIP ladder per call, with retransmission grouping and registration noise folded by default. Keep a way to inspect every raw packet.
7. Compare against a pinned known-good baseline with ignored differences shown explicitly; show why a run differs, not just an opaque hash.
8. Readable 13–14px code and 14–16px interface text, adjustable density, resizable navigation, keyboard shortcuts, accessible labels, and visible focus. Keep PASS/FAIL text and icons in addition to color.
9. Accounts: searchable list with alias, URI, transport, and registration-test status; show advanced parameters in a detail drawer. Use explicit password unchanged/replace/clear controls. Destructive actions belong in a clear menu with precise scope.

## Security and operations

`auth.go` uses one process-wide token for all logins; logout only deletes the browser cookie and cannot revoke a copied token. Expiry is client-side MaxAge, not a server-side expiry check. The cookie lacks Secure under HTTPS. Defaults expose a known password on all interfaces. The API key is written to a 0644 log; SQLite credentials are plain text, despite README language suggesting secure storage.

For this administrator-oriented application, a small expiring, revocable session store is sufficient. Use restrictive data/log permissions, safe first-run credentials, login throttling, HTTPS-aware cookies, bounded request bodies, HTTP header/idle timeouts, and graceful server shutdown. Protect recordings and webhook credentials as operational data. Do not add a large identity system unless actual multi-user requirements justify it.

Cron queue state is in memory, overflows only log, and scheduling time zone is implicit. Expose next/last run, explicit timezone, queued/skipped reason, and a policy for overlapping or stale triggers. Prefer coalescing monitor jobs over executing an hour of obsolete checks after a long outage. Share one execution/admission service between cron, API, and UI.

The external run API returns a generic started response without a durable batch ID or API-key-accessible result endpoint. Add `202` with run/batch ID, polling, cancellation, and JUnit output so CI can determine the actual outcome. Use a durable webhook outbox if notification delivery matters; surface failed deliveries and retry with backoff.

## Simplification and removal candidates

- Split `gobaresip` protocol/types from its cgo runtime. The purported pure-Go master currently imports the cgo package. The runner, parser, evaluator, store, and HTTP layer should be testable without native libraries even though the product remains Linux-only.
- Extract a runner service from `WsHub`. WebSocket transport should not own execution, verdicts, persistence, and process lifecycle.
- Retain process isolation and the text DSL. A framework rewrite or visual test builder is not the first investment.
- Remove the implicit default PASS, mock `stats`, and unsupported documentation claims; these create false confidence.
- Deprecate the custom G.722 module if upstream behavior meets the actual requirement. Keep small, documented native deltas with fixture tests rather than opaque source rewrites.
- Consolidate duplicate parameter normalization, JSON decoding/response conventions, event parsing, and frontend fetch handling.
- Audit unused convenience command wrappers, legacy helpers such as `CloseLogging`, and stale comments with symbol searches before deletion. Public package consumers may still matter.
- Replace the formatting test that manually reconstructs a netstring with tests of `Baresip.Cmd` itself. The added command transport test provides that seam; the old test was left untouched for this review.
- Replace repetitive helper-level hash tests with a small set of normalization fixtures and complete recorded-run acceptance tests. Keep tests proving separate contracts rather than deleting tests just to lower the count.
- Remove `TestParseDuration` in `cmdchain_test.go` when revising that suite: it calls the standard library directly and never exercises Telefonist. Test overflow/invalid delay handling through the actual DSL parser instead.
- Make `_tools/patcher` fail the build when any patch fails: it currently logs errors and exits successfully. Pin native dependencies to immutable revisions and verify downloaded archives; `rem` and the G.722 setup do not provide a fully reproducible source pin. Add Linux CI with the actual staged native libraries. Do not claim that `-ldflags -X` sets `Version` while it is declared as a Go constant.
- Correct README drift: login username is `admin`, the SIP listen default is empty, generated API keys go to the configured log, and validation examples need to match recorded evidence.

## Test work included and verification

Added nine top-level tests (the evaluator contract also has four scenarios):

- `pkg/gobaresip/command_transport_test.go`: actual concurrent `Cmd` writes over `net.Pipe`, Unicode byte lengths/framing, exact payloads, and a broken transport.
- `pkg/telefonist/api_accounts_test.go`: real SQLite-backed handlers; password omission/redaction, password preservation during metadata editing, and denial of unauthenticated mutation with no storage change.
- `pkg/telefonist/evaluator_test.go`: assertions consume recorded events, reject wrong order/agent/missing events, and interrupt an already-running infinite script on cancellation.
- `tests/web/contracts.test.mjs`: unsaved draft preservation on refresh, reconstruction of both runs from a diff with repeated SIP events, and 601 ordered WebSocket events across replay batches and frame budgets.

Verified here:

```text
node --test tests/web/contracts.test.mjs                         PASS (3 tests)
go test pkg/telefonist/evaluator.go pkg/telefonist/evaluator_test.go   PASS
git diff --check                                                PASS
```

Go tests above compile only the portable evaluator files, not Telefonist or its cgo dependencies. The local Go toolchain is 1.27rc2 on Windows; production Go 1.26/Linux validation remains necessary. Added API and transport tests have not been compiled/run here. No coverage percentage is claimed. Production source was left unchanged; the defects listed above remain open.

On Linux, after preparing the native dependencies:

```sh
make test
go test -race -coverprofile=coverage.out ./pkg/...
go tool cover -func=coverage.out
node --test tests/web/contracts.test.mjs
```

Use a modern Node version with ES-module syntax detection (verified with Node 24 here). Native C modules need separate ASan/UBSan runs: Go's race detector does not establish their memory safety.

High-value next tests, in order: loss invalidates verdict; cancellation always persists evidence; failed artifact moves preserve source; deletion stays inside its root; run admission excludes manual interference; hub-to-evaluator RTCP/timestamps survive; delayed saves stay attached to the original file; reconnect restores authoritative run state; retention removes actual files; native codec capacity boundaries. Add fuzzing around the DSL, strict netstrings, and SIP export once input limits are in place.

## Suggested delivery order

1. **Trust:** path-safe deletion, native bounds checks, explicit telemetry loss, fail-on-command-error, cancellation, durable failed runs, and safe recording finalization.
2. **Architecture:** separate runner/protocol from hub/cgo; immutable run/agent IDs; one event schema; one admission queue; deadlines and joined cleanup.
3. **Diagnosis:** semantic assertions, explicit baselines, run-first UI, synchronized inspection, reliable editor/reconnect behavior.
4. **Scale and automation:** retention, virtualized rendering, bounded/worker-based diffs, deterministic native builds, Linux CI, batch/result API, notification delivery.

Each step should ship with regression tests that fail on the concrete defect being corrected. Avoid setting a blanket coverage target until these workflows are protected.
